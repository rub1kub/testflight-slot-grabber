# Результаты исследования Proxyman

Проверено 4 августа 2026 года на этом Mac и только с локальной сессией владельца.

## Что удалось подтвердить

- Proxyman 6.14.0 видит процессы TestFlight и TLS-соединения с `testflight.apple.com`, `sandbox.itunes.apple.com` и `is1-ssl.mzstatic.com`.
- Без SSL Proxying Telegram-ссылка штатно открывается в TestFlight и показывает `Telegram Messenger` / `В этой программе бета-тестирования больше нет мест`.
- Временное client-rule `TestFlight` для SSL Proxying проверено сначала на тестовой ссылке, затем на заведомо доступной публичной бете Kashikan (`Ssjq4DbX`). В обоих случаях TestFlight показывал `Не удается открыть ссылку`.
- После удаления правила, выключения системного proxy и перезапуска TestFlight Telegram-ссылка снова открылась штатно.
- Все SSL Proxying rules удалены: старые `curl`, `Happ Plus` и созданное для исследования `TestFlight`. Системные HTTP/HTTPS proxy после эксперимента выключены.

## Вывод

В штатной конфигурации доступен только уровень TLS CONNECT/hosts. Обычное доверие локальному Proxyman CA не позволило безопасно расшифровать трафик TestFlight; это совместимо с дополнительной trust-политикой или pinning, но точную внутреннюю причину без запрещённого обхода определить нельзя. Pinning bypass, patching, injection, извлечение Apple credentials и сохранение HAR с токенами не выполнялись.

Реальный запрос принятия Telegram не возникал, потому что группа заполнена. Чужая доступная бета не принималась. Поэтому формат запроса, cookies/tokens, срок сессии и device binding не установлены, а API replay остаётся fail-closed и выключенным. Основной рабочий путь проекта — нативная AX UI-автоматизация.
